# CPA-постбэк: реальные данные о продажах для брендов

Статус: в разработке (ветка `feature/cpa-postback`)

## Проблема

Сейчас у продукта есть три способа монетизации куратора (промокод, CPA-сеть,
прямая договорённость), но ни один не даёт нам данные о реальных продажах —
только клики. Бренду нечего показать, кроме "перешли N раз", что не отвечает
на главный вопрос performance-маркетинга: сработало ли это в деньгах.

Из трёх путей только **CPA-сеть** технически позволяет получить подтверждённые
продажи автоматически — сеть (Admitad, ePN и т.п.) знает о покупке и может
уведомить нас через постбэк (server-to-server webhook) в момент подтверждения
заказа.

## Цель

Куратор и бренд видят не только клики, но и подтверждённые продажи/комиссию
по ссылкам, где подключена CPA-сеть — без ручного ввода, напрямую от сети.

## Как это должно работать

1. При формировании партнёрской ссылки в редиректе (`/r/[linkId]`) мы
   передаём в неё **свой идентификатор клика** как `subid` (или как называет
   этот параметр конкретная сеть — обычно `subid`, `clickid`, `ci`).
2. Сеть при подтверждении продажи стучится на наш **постбэк-endpoint**
   (`/api/postback/[network]`) и передаёт: `subid`, сумму заказа, размер
   комиссии, статус (pending / confirmed / rejected/ cancelled).
3. Мы сопоставляем `subid` с нашим кликом/ссылкой и сохраняем запись в новую
   таблицу `conversions`.
4. Данные показываются:
   - куратору — в медиаките, рядом с кликами: "продажи по CPA: N на сумму
     ...", по товарам, где это подключено;
   - бренду — в кабинете, у той же ссылки, что и клики.
5. Для ссылок без CPA-сети (обычные и промокодные) — никаких цифр продаж не
   показываем вообще, чтобы не создавать ложное ощущение, что мы что-то
   отслеживаем там, где физически не можем.

## Требования

### P0 — без этого нет реальных данных

- [ ] Таблица `conversions`: `id`, `link_id`, `network`, `external_id`
      (id заказа в сети, для дедупликации повторных постбэков),
      `click_id` (наш subid), `amount`, `commission`, `status`,
      `created_at`, `updated_at`.
- [ ] `subid`/`click_id` передаётся в аффилейт-ссылку при редиректе —
      расширить `resolveRedirectTarget`, чтобы шаблон бренда поддерживал
      плейсхолдер `{subid}` вместе с уже существующим `{url}`.
- [ ] Endpoint `POST /api/postback/[network]` — принимает данные от сети,
      проверяет секретный токен в query (`?token=...`, свой на сеть или на
      бренда), апсертит запись в `conversions` по `external_id` (защита от
      повторной обработки одного и того же постбэка).
- [ ] Хранить сырые постбэки (или как минимум лог последних N) для отладки
      интеграции — сети присылают данные в разных форматах, будет нужно
      подстраиваться под конкретную сеть при реальном подключении.

### P1 — чтобы это было видно и полезно

- [ ] Медиакит куратора — блок "Продажи по CPA" рядом с кликами, только
      для ссылок, где есть хотя бы один конверсия.
- [ ] Кабинет бренда — то же самое, в списке "Кто ссылается на ваши товары".
- [ ] Статусы конверсии видны отдельно (подтверждено / в ожидании /
      отклонено) — сети обычно подтверждают заказ не сразу, отменённые
      заказы должны вычитаться, а не завышать цифру.

### P2 — не сейчас, но не должно быть заблокировано архитектурой

- Поддержка нескольких сетей одновременно с разными форматами постбэка
  (уже заложено полем `network` в таблице).
- Автоматическая сверка сумм комиссии для выплат куратору — сейчас Shoppi
  не участвует в движении денег, только в трекинге; если это изменится,
  понадобится отдельная модель.

## Открытые вопросы

**Блокирующие**

1. У какой именно CPA-сети будет первый реальный контракт — формат постбэка,
   имя параметра subid и способ авторизации запроса разные у каждой сети
   (Admitad, ePN и т.д.). Без этого можно построить только универсальный
   каркас, не рабочую интеграцию с конкретной сетью.
2. Что считать "продажей" для отображения бренду — учитывать ли `pending`
   (ещё не подтверждённые сетью) заказы в цифрах, или показывать только
   `confirmed`.

**Неблокирующие**

3. Нужен ли UI для бренда, чтобы вручную вводить секрет/настройки постбэка
   своей CPA-сети, или пока хватит одного общего токена на всех.

## Что НЕ входит в эту задачу

- Промокоды и прямые договорённости — по ним нет автоматических данных о
  продажах, это осознанно вне скоупа (см. критику выше в анализе
  монетизации).
